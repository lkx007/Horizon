### [Matrix multiplication exponent proven to be 9/4 in new theoretical breakthrough](https://scottaaronson.blog/?p=10379) ⭐️ 9.0/10

A newly announced proof claims the matrix multiplication exponent ω equals 9/4 \(2.25\), a strict improvement over the previous best upper bound of approximately 2.3718 \(achieved by Alman and Vassilevska Williams in 2021\). The result, if verified, would resolve a central open problem in theoretical computer science and imply asymptotically faster algorithms for matrix multiplication and dozens of derived problems including graph transitive closure, solving linear systems, and certain dynamic programming tasks. The proof is presented in a linked PDF titled &\#x27;The matrix multiplication exponent is nine fourths&\#x27; and has triggered intense scrutiny and discussion on Hacker News, with no independent verification or peer-reviewed publication yet reported.

hackernews · Kotlopou · Nov 25, 19:11 · [Discussion](https://news.ycombinator.com/item?id=50646108)

**「Matrix multiplication exponent background」** The matrix multiplication exponent ω is the smallest real number such that two n×n matrices can be multiplied using O\(n^ω+ε\) arithmetic operations for any ε &gt; 0. For over five decades, ω has been known to satisfy 2 ≤ ω &lt; 2.3728596 \(the current best upper bound prior to this result, due to Duan, Wu, and Zhou in 2023\). A proof that ω = 9/4 = 2.25 would represent a sharp, exact determination—breaking the long-standing pattern of incremental upper-bound improvements—and would resolve a central open problem in algebraic complexity theory.

**「Impact」** If confirmed, the result would require updates to graduate-level algorithms and complexity theory curricula, invalidate decades of conditional lower bounds predicated on ω &gt; 2.25, and motivate hardware-aware algorithm redesigns for high-performance computing libraries—though no implementation or benchmarking is cited in the source material.

**「Community discussion」** Commenters debate whether this breakthrough signals a broader shift in mathematical discovery, with one arguing humans are biologically unequipped to grasp its significance \(&\#x27;cognitive baton hand-off&\#x27;\), while another questions whether formal verification tools like Lean and MathLib—not LLMs—were already sufficient to enable such advances given their decade-long maturation.

The flaw enables arbitrary code execution on Windows clients \(e.g., version 26.3\), with a publicly disclosed proof-of-concept as of November 22, 2026. Mojang has not released an official patch and continues using lwjgl-freetype 3.4.3; the community released m2sfix 1.0.0 on November 24, 2026, as a Java agent or mod that disables font hinting to mitigate the issue. Versions 1.20.4 and earlier, and Bedrock Edition, are unaffected.

telegram · zaihuapd · Nov 25, 12:46

The vulnerability exploits memory corruption in FreeType versions 2.14.3 and earlier—specifically an out-of-bounds write during TrueType font hinting—which can be triggered by maliciously crafted fonts distributed through resource packs.

**「Impact」** Users running Minecraft Java Edition 1.20.5 through 1.21.10 or snapshots 26.1–26.4 are at immediate risk of arbitrary code execution when accepting or manually enabling a malicious resource pack containing a crafted TrueType font; Mojang has not yet released an official patch, leaving mitigation dependent on disabling resource packs or installing community-provided fixes like m2sfix 1.0.0.

### [GRH Lean verification reduced from 17M to 76k lines](https://github.com/lsernau/grh-lean) ⭐️ 8.0/10

Anthropic researchers have released a dramatically shortened Lean formalization of the Graph Regularity Lemma \(GRH\), reducing it from approximately 17 million lines of code to about 76,000 lines—a 99.56% reduction. The new version, hosted at github.com/lsernau/grh-lean, prioritizes readability, human documentation, and clear separation between established mathematics and novel contributions. It is not an automated compression but a manually refined, insight-oriented reimplementation intended to improve accessibility and mathematical understanding.

hackernews · nb-t · Nov 25, 21:48 · [Discussion](https://news.ycombinator.com/item?id=50648050)

**「Graph Regularity Lemma and Lean formalization」** The Graph Regularity Lemma \(GRL\) is a foundational result in extremal graph theory, originally proved by Endre Szemerédi, that guarantees any large graph can be partitioned into a bounded number of parts such that most pairs of parts behave pseudorandomly. Formalizing it in Lean—a functional programming language and interactive theorem prover—requires encoding its combinatorial definitions, iterative constructions, and quantitative bounds with machine-checked precision; the original formalization spanned approximately 17 million lines of Lean code.

**「Enables human comprehension of the GRH formal proof」** The reduction from ~17 million to ~76,000 lines of Lean makes the Graph Regularity Lemma formalization tractable for human review and pedagogical use—addressing a core limitation highlighted by Terence Tao’s concern about unreadable, insight-free formal proofs.

**「Community discussion」** Commenters highlight the improved clarity and documentation in the new proof, with one noting its explicit &\#x27;known math&\#x27; vs &\#x27;new math&\#x27; split; another questions whether such LLM-assisted proof compression addresses Terence Tao’s recent concern about large, insight-poor formal proofs, while a third expresses a desire for a traditional mathematical exposition alongside the Lean code.

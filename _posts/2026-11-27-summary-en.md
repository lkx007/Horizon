### [NFS2ROOT: 12-year-old pre-auth remote root vulnerability CVE-2026-99362 in Linux kernel NFS server](https://opensec.in/blog/nfs2root-cve-2026-99362) ⭐️ 9.0/10

A critical pre-authentication remote code execution vulnerability, CVE-2026-99362 \(dubbed &\#x27;NFS2ROOT&\#x27;\), has been disclosed in the Linux kernel&\#x27;s in-kernel NFS server implementation. The flaw exists in NFSv2 request handling and affects all Linux kernel versions from 3.10 \(released in 2013\) through 6.12, enabling unauthenticated attackers to achieve remote root privileges. It is exploitable without prior authentication or user interaction and applies to systems where the kernel NFS server \(nfsd\) is enabled and exposed to untrusted networks. No patch is included in the report, and mitigation relies on external measures such as network filtering or disabling NFSv2.

hackernews · dm · Nov 25, 20:35 · [Discussion](https://news.ycombinator.com/item?id=50647161)

**「NFS server implementation in the Linux kernel」** The Linux kernel has included an in-kernel NFS server since version 2.6.30 \(released in 2009\), supporting NFSv2, NFSv3, and later NFSv4. This design prioritizes performance by avoiding userspace–kernelspace context switches but increases attack surface, as vulnerabilities in the server code execute with kernel privileges. Userspace alternatives like nfs-ganesha exist but are not default or widely deployed in mainstream distributions.

**「Immediate remote root compromise for exposed NFS servers」** Any Linux system running the in-kernel NFS server \(nfsd\) and exposing port 2049 to untrusted networks is immediately vulnerable to remote pre-authentication root code execution; no authentication or prior access is required, and the flaw affects all kernel versions containing the vulnerable nfsd4\_sequence\(\) logic dating back 12 years.

**「Community discussion」** Commenters debate the architectural risk of implementing NFS in-kernel, with one noting userspace alternatives exist but lack adoption and maintenance; another highlights an XDP-based L7 firewall rule published to mitigate the flaw via the &\#x27;yeet&\#x27; project. A third commenter questions whether running NFSv4 behind spiped provides sufficient protection, implying uncertainty about protocol-layer exposure.

### [Matrix multiplication exponent claimed reduced to 9/4](https://scottaaronson.blog/?p=10379) ⭐️ 8.0/10

A claimed theoretical breakthrough has lowered the matrix multiplication exponent ω to 9/4 = 2.25, as reported on Scott Aaronson’s blog and linked from a Hacker News post. This would improve upon the current best proven upper bound of ω &lt; 2.37158 \(Alman &amp; Vassilevska Williams, 2021\) and represent the first major reduction in decades. The claim is not yet peer-reviewed or widely verified; the source material does not include the proof, its authors, or publication venue, and no implementation or empirical validation is described. The announcement appears to be a preprint or informal report, not a shipped algorithmic library or software release.

hackernews · Kotlopou · Nov 25, 19:11 · [Discussion](https://news.ycombinator.com/item?id=50646108)

**「What is the matrix multiplication exponent?」** The matrix multiplication exponent, denoted ω, is the smallest real number such that two n×n matrices can be multiplied using O\(n^ω\) arithmetic operations; the longstanding conjecture is that ω = 2. Prior to this claim, the best proven upper bound was ω ≤ 2.371552 \(Alman &amp; Vassilevska Williams, 2021\), improving on decades of incremental progress from Strassen’s 1969 algorithm \(ω ≤ log₂7 ≈ 2.807\).

**「Impact」** If verified, the claimed exact matrix multiplication exponent of 9/4 \(2.25\) would imply that no algorithm can multiply n×n matrices using fewer than Ω\(n^\{9/4\}\) arithmetic operations—establishing a tight lower bound and closing a decades-old open problem in theoretical computer science; this would constrain the asymptotic efficiency of all algorithms relying on matrix multiplication, including many in machine learning, scientific computing, and graph theory.

**「Community discussion」** Hacker News commenters express skepticism about immediate cryptanalytic implications, with one arguing that no evidence exists for secret cryptosystem breaks by AI labs, citing organizational scale and leak risk as barriers; another reflects on human cognitive limits in grasping the magnitude of such theoretical advances.

### [Register Recycling for NVFP4 Attention on NVIDIA RTX Blackwell](https://developer.nvidia.com/blog/how-to-optimize-nvfp4-attention-on-nvidia-rtx-blackwell-through-register-recycling/) ⭐️ 9.0/10

rss · NVIDIA Technical Blog · Nov 25, 19:30

**「Background」** Attention kernels on NVIDIA RTX Blackwell \(SM120\) GPUs are bottlenecked by Tensor Core idle time during NVFP4 attention—unlike data-center Blackwell variants, where softmax dominates. The original SageAttention3 kernel executed QK, softmax, quantization, and PV sequentially per N128 tile, leaving large gaps in MMA utilization due to register exhaustion \(95.3% used\) and rigid pipeline dependencies.

**「Solution」** The author introduces register recycling: splitting each N128 score tile into two N64 register slots and reusing them mid-tile. After exponentiating and quantizing the first N64 half, its registers are immediately repurposed for QK computation of the \*next\* tile—overlapping that work with the current tile’s remaining softmax, scaling, and PV operations. This cross-tile ping-pong preserves the same 12-warps-per-CTA structure and avoids a second full score buffer, while filling Tensor Core gaps without increasing register pressure. Microbenchmarks show 1.17–1.64× speedup across sequence lengths and masks; production end-to-end inference on Reactor’s world models achieved up to 15.34% latency reduction, with the optimization merged into FlashInfer.

**「Takeaway」** Register recycling—reclaiming score registers \*during\* tile processing to interleave QK of the next tile with softmax/quantization of the current—is a hardware-aware, register-constrained scheduling insight that unlocks higher Tensor Core utilization for NVFP4 attention on SM120, delivering measurable real-world latency gains without architectural changes or extra memory.
